Catalogue ACS: Multi-Cluster GitOps Deployment Platform

A self-service platform letting engineers browse a Helm chart catalogue and deploy applications to Rancher-managed Kubernetes clusters through GitOps, with real-time status streaming and zero manual YAML editing. Built end-to-end during my internship at Atlas Cloud Service, from the Next.js wizard to the Fleet-synced cluster rollout.

3-step deploy wizard Zero manual YAML Real-time SSE status Multi-cluster GitOps Vault-backed secrets Keycloak OIDC RBAC
Kubernetes Rancher Fleet Helm GitLab CI/CD HashiCorp Vault External Secrets Operator Harbor Spring Boot Next.js PostgreSQL Redis Keycloak/OIDC MinIO Server-Sent Events

Architecture: from wizard submit to cluster rollout

Full-stack platform

Next.js 16 (App Router) frontend backed by a Spring Boot 4 / Java 21 API, deployed as one Helm chart with its own Fleet GitOps bundle, Vault SecretStore, ExternalSecrets, and an nginx ingress with TLS from cert-manager and Let's Encrypt.

3-step deploy wizard

Select cluster, chart version and namespace, configure Helm values, then review and submit. The backend commits fleet.yaml and values.yaml straight into the GitLab GitOps repo; Rancher Fleet picks up the commit and syncs it to the target cluster.

Live status over SSE

Deployment progress streams to the browser via Server-Sent Events. Because EventSource cannot carry a JWT header, the API issues short-lived one-time tickets that bridge JWT authentication to the SSE stream.

Redis multi-tier caching

Spring Cache on Redis cuts redundant Rancher and registry calls, with TTLs tuned per data volatility: 10 minutes for catalogue data, 30 seconds for Fleet bundle polling.

Secrets never reach the frontend

Rancher API tokens are AES-256-GCM encrypted server-side. Production secrets for the database, Keycloak, GitLab and Harbor are pulled from HashiCorp Vault by the External Secrets Operator instead of living in Helm values.

Helm chart import pipeline

Discovers chart versions from OCI and classic Helm registries and automatically replicates the referenced container images into a private Harbor registry, so clusters only pull from trusted sources.

Keycloak OIDC with RBAC

NextAuth.js on the frontend and Spring Security Resource Server on the backend, with superuser / admin / developer / viewer roles enforced both in route guards and via @PreAuthorize on the API.

Durable audit trail

Audit events are written as NDJSON files to MinIO (S3-compatible) rather than a database table, giving a durable, queryable compliance trail that survives independently of the application database.
